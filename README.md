# 콜드메일 라이브 테스트 (coldmail-preview)

**▶ https://namiruan.github.io/coldmail-preview/**

HTML 이메일 코드를 **메일 클라이언트에서 실제로 보이는 모습**으로 미리보는 도구입니다.
Gmail 스타일 셸 안에 HTML을 렌더링해서, 보내기 전에 레이아웃이 깨지는지 확인합니다.

- 데스크톱 / 모바일 뷰 전환
- 라이트 모드 + **Gmail 자동 다크모드 시뮬레이션** (`color-scheme` 선언이 없는 메일을 Gmail이 반전시키는 동작을 근사)
- `<title>` 태그에서 메일 제목 자동 추출
- 화면은 [김반장 3.0 디자인 시스템](https://github.com/namiruan/kbz_3.0_ui_stytem)을 따릅니다

## 화면

한 화면에서 **시안 목록 · 미리보기 · 코드 에디터**를 함께 봅니다.
`라이브 에디터` 를 누르면 오른쪽에 에디터가 열리고, 고치는 즉시 미리보기에
반영됩니다. 목록이 그대로 남아 있어 시안을 오가며 코드를 볼 수 있습니다.

**에디터에 보이는 코드가 곧 메일에 붙여 넣을 코드입니다.** 변형마다 파일이
따로 있어 `<title>` 과 UTM이 파일 안에 이미 들어 있습니다. 코드를 다시 쓰는
단계가 없으니 `복사` 한 것을 그대로 보내면 됩니다.

편집한 내용은 **그 자리에서만** 유지됩니다 — 시안을 바꾸거나 `초기화` 를
누르면 파일 원본으로 돌아갑니다. 저장하려면 `커밋` 으로 GitHub에서 반영합니다.

| 경로 | 설명 |
| --- | --- |
| `/` | 미리보기 |
| `/editor` | 같은 화면을 에디터가 열린 채로 (예전 링크 호환) |

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
```

| 스크립트 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | `dist/` 로 프로덕션 빌드 |
| `npm run preview` | 빌드 결과물을 로컬에서 서빙 |
| `npm run typecheck` | `tsc --noEmit` 타입 검사 |
| `npm run validate` | `templates/README.md` 검증 |
| `npm run sync:kbz` | 김반장 3.0 디자인 시스템 토큰·컴포넌트 다시 받기 |

## 배포

`main`에 푸시하면 `.github/workflows/deploy.yml`이 typecheck → build → GitHub Pages 배포를 자동으로 수행합니다. 따로 할 일은 없습니다.

Pages는 `https://<user>.github.io/<repo>/` 하위 경로로 서빙되므로 빌드 시 `VITE_BASE`를 넘깁니다. 라우터도 `import.meta.env.BASE_URL`에서 basename을 읽어 맞춥니다. 로컬 `npm run dev`는 루트(`/`) 기준이라 신경 쓸 필요가 없습니다.

`createBrowserRouter`를 쓰기 때문에 `/editor`로 직접 들어가거나 새로고침하면 Pages가 404를 반환합니다. 워크플로가 `index.html`을 `404.html`로 복사해 두어, 그 안의 클라이언트 라우터가 경로를 처리합니다.

> ⚠️ 이 저장소는 **public**입니다. `templates/` 의 템플릿 내용(가격 포함)은 빌드된 JS 번들에 그대로 들어가며, 배포된 사이트에서 누구나 읽을 수 있습니다.

## 구조

```
src/
  main.tsx                     진입점
  app/
    App.tsx                    RouterProvider + Toaster
    routes.tsx                 라우트 정의
    components/
      EmailPreview.tsx         시안 목록 + 메일 클라이언트 셸 + 렌더링
      EditorPanel.tsx          오른쪽 코드 에디터 (CodeMirror · HTML 린터)
      ui/                      shadcn/ui 컴포넌트
    data/
      defaultTemplates.ts      templates/README.md 를 읽어 시안 목록을 만든다
      parseTemplatesDoc.js     그 문서의 표를 읽는 파서 (검증 스크립트와 공용)
      utm.ts                   문서에 적는 UTM 값의 타입 (문서↔파일 대조용)
      repo.ts                  GitHub 링크 (읽기 · 편집)
  styles/
    kbz/tokens.css             김반장 3.0 토큰 (자동 생성 — 고치지 않는다)
    kbz/components.css         쓰는 컴포넌트 CSS (자동 생성 — 고치지 않는다)
    app.css                    이 앱의 화면. 위 토큰만 쓴다
```

템플릿을 추가하거나 고치려면 `templates/` 의 `.html` 파일을 편집하고 커밋합니다.
목록 순서·묶음·상태는 `templates/README.md` 이 결정합니다. 제목과 UTM은
`.html` 안에 있고, 문서의 UTM 칸은 그 값을 옮겨 적은 대조표입니다.

## 분류와 그룹

목록은 **분류 → 그룹 → 시안** 세 층으로 보입니다.

| 분류 | 성격 | A/B 테스트 | 그룹 |
| --- | --- | --- | --- |
| `콜드메일` | 먼저 보내는 영업 메일 | 대상 | 안면인식서비스 · 퇴직공제 |
| `발신템플릿` | 요청에 응답해 보내는 메일 | 하지 않음 | 홈페이지용 · 인트라넷용 |

분류와 그룹 모두 **이름이 같으면 표에서 떨어져 있어도 한 묶음**이 됩니다.
묶음의 자리는 그 이름이 처음 나온 줄, 묶음 안 순서는 표의 순서를 따릅니다.
그래서 표는 ID 순서를 그대로 두면 됩니다.

## 사용 상태

시안마다 상태를 하나 갖습니다. **어느 상태든 UTM 설정은 그대로 남아서**,
되돌리면 바로 다시 쓸 수 있습니다. 쓰지 않게 된 시안을 지우지 마세요.

| 상태 | 뜻 | 목록 표시 | 목록에서 |
| --- | --- | --- | --- |
| `사용중` | 지금 쓰는 시안 | 채운 초록 원 | 그대로 보임 |
| `미사용` | 시안은 있으나 아직 쓰기 전 | 빈 파란 원 | 그대로 보임 |
| `운영종료` | 집행을 마친 시안 | 회색 네모 | 숨겨짐 — `운영종료 N` 을 눌러야 보임 |

상태는 이름 왼쪽 고정 위치의 도형으로 표시합니다. 색만으로 가르면 색각 이상인
사람이 구분하지 못하므로 **도형도 함께** 다릅니다. 뜻은 목록 맨 아래 범례에
있고, 행에 마우스를 올리면 상태 이름이 뜹니다.

`미사용`·`운영종료` 시안을 열면 본문 위에 안내가 뜹니다. 모르고 발송하는 걸 막습니다.

> 상태는 문서에 있으니 git에 남고 팀 전체가 같은 값을 봅니다. 반면 `운영종료 N`
> 토글은 **보기 설정이라 브라우저에만 저장**되어 사람마다 따로입니다.

각 `.html` 은 **한 겹짜리 문서**여야 합니다. `<!DOCTYPE>`·`<html>`·`<body>` 가
두 번 이상 나오면 배포가 막힙니다. 브라우저는 겹친 문서를 너그럽게 렌더하지만
메일 클라이언트는 어느 `<head>` 를 살릴지 제각각이라, 미리보기만 멀쩡하고 실제
발송에서 깨질 수 있습니다.

> `templates/README.md` 는 GitHub에서 직접 고치는 문서입니다. 표가 깨지거나
> 파일명·상태 값이 틀려도 빌드는 통과하므로, 배포 전에 `npm run validate` 가
> 돌아갑니다 — 빈 칸, ID·시안 중복, 없는 파일, 표에 없는 html, 상태 값, 문서와
> 파일의 UTM 불일치, 문서 겹침을 확인하고 문제가 있으면 **배포를 막습니다.**
> 실패하면 라이브는 직전 정상 버전 그대로 유지됩니다.

## A/B 테스트와 UTM

**변형마다 파일이 하나입니다.** 본문이 다르든 제목만 다르든 마찬가지입니다.
`<title>` 과 `utm_*` 가 파일 안에 들어 있으므로, 에디터가 보여주는 코드가 그대로
보낼 코드입니다. 코드가 링크를 다시 쓰는 단계는 없습니다.

`## 시안` 표에 줄을 둘 적고 `시안` 칸에 `A`·`B` 를 넣습니다. 분류·그룹·이름이
같으면 한 항목으로 묶여 목록에 `시안 A B` 토글이 생기고, 고른 쪽의 `.html` 로
원본 링크가 갑니다.

```
## 시안
| ID | 분류 | 그룹 | 이름 | 시안 | 파일 | 상태 | source | medium | campaign | content |
| 08 | 콜드메일 | 퇴직공제 | 26.04.02~26.04.06 | A | 08a-premium-title-ab.html | 운영종료 | coldmail | email | title_ab | - |
| 08 | 콜드메일 | 퇴직공제 | 26.04.02~26.04.06 | B | 08b-premium-title-ab.html | 운영종료 | coldmail | email | title_ab | - |
```

A/B 묶음은 **ID를 공유**합니다 — 같은 집행이기 때문입니다. 줄을 가리는 키는
`ID + 시안`(`08a`·`08b`) 이고, 파일명 앞머리와 같게 두면 읽기 쉽습니다.
한 항목의 시안끼리는 상태를 맞춰야 합니다 — 어긋나면 배포가 막힙니다.

**UTM 칸은 파일 안 링크에 적힌 값을 옮겨 적는 자리입니다.** 문서가 원본이 아니라
**대조표**입니다 — 문서와 파일이 어긋나면 `npm run validate` 가 배포를 막습니다.
한 파일 안에서 링크마다 값이 갈리는 시안은 `-` 로 비워 둡니다.

검증은 같은 묶음의 시안끼리 본문(제목·UTM 제외)이 같은지도 알려 줍니다.

```
A/B: 단일홍보 본문도 다름 · 26.04.02~26.04.06 제목만 다름
```

제목만 다를 셈이었는데 `본문도 다름` 이 나오면 한쪽만 고친 것입니다. 반대로
본문부터 다른 A/B(단일홍보)는 원래 그런 것이라 막지 않습니다.

제목은 HTML의 `<title>` 에서 읽습니다. `<title>` 이 없으면 비워 둡니다.

## 디자인 시스템

화면은 [김반장 3.0 디자인 시스템](https://github.com/namiruan/kbz_3.0_ui_stytem)을 따릅니다.
색·간격·크기·서체는 전부 토큰에서 가져옵니다 — **이 저장소에서 새 색값을 정하지 않습니다.**

```bash
npm run sync:kbz                      # GitHub main 에서 받기
node scripts/sync-kbz.mjs ../kbz_3.0_ui_stytem   # 로컬 체크아웃에서 받기
```

받아 오는 것은 두 가지입니다.

| 파일 | 내용 |
| --- | --- |
| `src/styles/kbz/tokens.css` | 토큰 번들 **원본 그대로** |
| `src/styles/kbz/components.css` | 쓰는 컴포넌트의 CSS만. 각 스펙 문서의 ` ```css ` 블록에서 뽑습니다 |

쓰는 컴포넌트는 Button · Badge · Segment · Banner · Toast · Icon Button 입니다.
(Icon Button은 `utilities/icon.css` 가 토큰 번들에 함께 들어와 따로 받지 않습니다.)
늘어나면 `scripts/sync-kbz.mjs` 의 `COMPONENTS` 목록에 적고 다시 받습니다.

### 시안 목록

왼쪽 목록은 김반장 `prototype/chrome.css` 의 **시나리오 네비게이션**을 그대로 옮긴
것입니다. 거기 적힌 판단 셋이 이 목록에도 그대로 맞습니다.

1. **목록 글자는 본문색이다** — 회색으로 두면 전부 "꺼져 있는 것"처럼 보이고
   켜진 하나만 읽히는 목록이 됩니다. 고르라고 늘어놓은 것인데.
2. **활성은 면으로 표시한다** — 왼쪽 2px 선은 목록이 길어지면 무엇이 켜졌는지
   한눈에 안 들어옵니다. 면은 멀리서도 하나만 보입니다.
3. **번호 열이 묶음을 그린다** — 레이블 아래로 이어지는 번호가 곧 "이 묶음"이라
   왼쪽 세로선도 들여쓰기도 따로 필요 없습니다.

번호는 `templates/README.md` 의 **ID** 입니다 — 목록과 문서를 같은 번호로 오갑니다.

줄은 세 개의 열로 섭니다. 왼쪽부터 **상태 → 번호 → 이름**이고, 이름이 서는
자리가 `--rail-name-col` 입니다.

| | 들여쓰기 | 왜 |
| --- | --- | --- |
| 대분류 | 줄의 왼쪽 끝 | 가장 바깥. 위의 선·자간·본문색이 구역임을 말합니다 |
| 그룹 | `--rail-name-col` | **제 항목들의 이름과 같은 선** — 그 열의 머리글이 됩니다. 셰브런은 그 왼쪽에 걸칩니다 |
| 항목 이름 | `--rail-name-col` | 번호 열이 왼쪽에 곧은 한 줄로 남습니다 |

### 이 규칙 밖에 있는 것

- **네이버 메일 미리보기**(`DesktopEmailClient` · `MobileEmailClient`) — 네이버 UI를
  흉내 내는 것이 목적이라 네이버 색을 그대로 씁니다.
- **코드 에디터 안쪽** — 어두운 면 위에서 코드를 읽는 관행을 따릅니다. 색은
  김반장 팔레트(`--color-gray-950`·`--color-blue-300` 등)에서 가져오되, 밝은 면이
  아니라 어두운 면 위에서 씁니다. 밝은 면이면 구문 색을 흰 배경에서 4.5:1로
  맞춰야 하는데 `-600` 계열만으로는 서로 구분이 안 됩니다.

### 디자인 시스템이 아직 다루지 않는 것

`src/styles/app.css` 맨 아래에 모아 두었습니다. 토큰만 써서 메웁니다.

- **아이콘+글자 Segment** — 스펙의 Segment는 글자 전용이라 아이콘 간격(gap)이 없습니다.
- **어두운 면 위의 버튼 비활성** — `btn--inactive` 의 회색 면은 밝은 배경 기준이라
  어두운 바에서 밝게 튑니다.
- **아이콘** — 디자인 시스템 아이콘 63개 중 이 화면에 필요한 Mail·Monitor·Smartphone·
  Sun·Moon·Code·GitBranch 가 없어 lucide를 씁니다. 크기·색만 토큰(`--icon-*`)을 따릅니다.
- **링크인 Icon Button** — Icon Button의 hover·pressed 는 `button` 요소에만 걸려
  있습니다. 참고 문서로 가는 길은 `<a>` 가 맞아서(`button.md`: 페이지 이동은 `<a>`)
  같은 상태를 앱에서 따로 줍니다.
- **중립 계열로 켜지는 필터** — `운영종료 N` 은 누르는 필터라 스펙상 Tag 인데,
  Tag의 selected 는 브랜드색 하나뿐입니다. 끝난 시안을 거르는 버튼이 켜졌다고
  파랗게 되면 "지금 쓰는 것"으로 읽힙니다. 그래서 중립 Badge 를 버튼으로 쓰고,
  보이는 중/숨긴 중은 면 채움과 눈 아이콘으로 가릅니다. **Tag에 중립 selected
  변형이 있으면 이 예외가 없어집니다.**

### 다크 모드

디자인 시스템에 다크 테마가 없으므로 **앱 화면은 항상 밝은 면**입니다.
머리말의 `라이트`·`다크` 전환은 **메일 클라이언트 미리보기에만** 적용됩니다 —
Gmail이 다크모드에서 메일을 어떻게 반전하는지 보는 것이 그 토글의 일이고,
앱 화면까지 같이 어두워질 이유는 없습니다.

## 이 저장소와 Figma Make

이 코드는 Figma Make에서 한 번 내보낸 뒤로 **git이 유일한 원본(source of truth)** 입니다.
